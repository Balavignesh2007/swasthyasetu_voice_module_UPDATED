# SwasthyaSetu ASHA Worker App (Flutter)

A Flutter frontend for community health workers (ASHA) to receive, acknowledge,
and resolve emergency alerts generated by the SwasthyaSetu Voice Helpline
backend — plus a view of their assigned patients.

This connects to the FastAPI backend in `../backend` via direct REST calls
(no push notifications yet — see "Adding push notifications" below).

## What's included

```
lib/
├── main.dart                    # entrypoint, session-aware startup routing
├── config.dart                  # API base URL, poll interval
├── models/
│   ├── emergency_alert.dart     # mirrors backend EmergencyEventOut schema
│   └── patient.dart             # mirrors backend patient/worker JSON
├── services/
│   ├── api_service.dart         # all REST calls to the backend
│   └── session_service.dart     # local persistence of logged-in ASHA worker
├── screens/
│   ├── login_screen.dart        # phone-number based identity lookup
│   ├── home_screen.dart         # bottom-nav shell (Alerts / Patients)
│   ├── alerts_screen.dart       # polls backend, lists open alerts
│   ├── alert_detail_screen.dart # acknowledge/contacting/reached/escalate/resolve
│   └── patients_screen.dart     # assigned patient list
└── widgets/
    ├── alert_card.dart
    └── status_badge.dart
```

## Backend endpoints this app calls

| App action | Backend endpoint |
|---|---|
| Log in by phone | `GET /api/v1/asha/lookup?phone=...` |
| Load alerts | `GET /api/v1/asha/alerts?asha_id=...` |
| Acknowledge | `POST /api/v1/asha/alerts/{id}/acknowledge` |
| Mark contacting | `POST /api/v1/asha/alerts/{id}/contacting` |
| Mark reached | `POST /api/v1/asha/alerts/{id}/reached` |
| Unable to reach | `POST /api/v1/asha/alerts/{id}/unable-to-reach` |
| Escalate | `POST /api/v1/asha/alerts/{id}/escalate` |
| Resolve | `POST /api/v1/asha/alerts/{id}/resolve` |
| Patient list | `GET /api/v1/asha/{asha_id}/patients` |

The `lookup`, alert-list, and patient-list endpoints were added to the
backend's `app/api/asha.py` alongside this app — pull the latest backend code
if you generated it before this app.

## Setup

This repo ships only the `lib/` Dart source and `pubspec.yaml` — platform
folders (`android/`, `ios/`, etc.) are generated by the Flutter tool, since
they're large and machine/SDK-specific.

```bash
cd asha_app

# Generate platform scaffolding (android/, ios/, etc.) in this existing folder
flutter create --project-name swasthyasetu_asha_app .

# Install dependencies
flutter pub get

# Run against your backend (adjust the URL for your setup — see below)
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

### Pointing at the backend

`lib/config.dart` reads `API_BASE_URL` from a Dart define, defaulting to
`http://10.0.2.2:8000` (the special address an Android emulator uses to reach
your host machine's `localhost`).

- **Android emulator** + backend running on your host: keep the default, or
  pass `--dart-define=API_BASE_URL=http://10.0.2.2:8000`.
- **iOS simulator** + backend on your host: use
  `--dart-define=API_BASE_URL=http://localhost:8000`.
- **Physical device**: use your machine's LAN IP, e.g.
  `--dart-define=API_BASE_URL=http://192.168.1.50:8000`, and make sure your
  phone and backend are on the same network (or use ngrok's HTTPS URL).
- **Production**: your deployed HTTPS backend URL.

Make sure the backend is actually running first:
```bash
cd ../backend
uvicorn app.main:app --reload --host 0.0.0.0
```

### Logging in

The login screen asks for the ASHA worker's registered phone number and
resolves it via `GET /api/v1/asha/lookup`. Seed a demo worker first:
```bash
cd ../backend
python scripts/seed_demo_data.py   # creates ASHA "Lakshmi Devi", phone +919876543210
```
Then log in with `+919876543210` in the app.

### Triggering a test alert

Call the backend directly to simulate an emergency detected on a voice call:
```bash
curl -X POST http://localhost:8000/api/v1/emergency-events \
  -H "Content-Type: application/json" \
  -d '{"call_session_id": "test-call-1", "red_flag_type": "Severe Chest Pain with Breathing Difficulty"}'
```
It should appear at the top of the Alerts screen within one poll cycle
(15 seconds by default — see `AppConfig.alertsPollInterval`).

## Known gaps / next steps

1. **Authentication** — login is phone-number lookup only, no password/OTP/JWT
   session yet. The backend already has JWT helpers
   (`backend/app/utils/security.py`) — wire `create_access_token` into the
   lookup endpoint and have `ApiService` attach a Bearer token once you're
   ready to harden this.
2. **Push notifications** — the app currently polls every 15 seconds. For
   real-time emergency alerts, add Firebase Cloud Messaging: register the
   device token with the backend (extend `AshaWorker` with a device-token
   field) and have `NotificationService.send_push_to_asha` on the backend
   call FCM instead of just logging.
3. **Offline support** (spec section 39) — not implemented here; this app
   assumes connectivity. Add local caching (e.g. `sqflite` or `hive`) plus a
   pending-sync queue for offline-first acknowledgement.
4. **Error/retry polish** — network errors surface as plain text; consider a
   proper offline banner and automatic retry with backoff for the poller.
